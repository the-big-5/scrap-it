# Flows
## F1: Sign in [Locked]
1. User opens app
2. Not signed in: presented with 3 onboarding slides on launch before reaching the Welcome screen (change 074). Completing slide 3 ("Let's Try It") smoothly dissolves to Welcome. User taps "Sign in with Apple"; Apple verifies the Apple Account (Face ID / passcode). Only on success is the profile created (or loaded). Requested data: full name and email. Apple sends the name and email only on the first authorization; when it does, the profile name (unless customized) and read-only email are set or updated. Without a name, a new profile is called "Friend". After sign-in from Welcome, user navigates directly to Home (changes 053, 074)
3. Already signed in (saved Apple user ID + local profile):
   - Online: checked with Apple on launch. Authorized → straight to Home. Revoked, not found, transferred, or check error → Welcome
   - Offline: straight to Home with local data; the Apple check runs once the network is back, and anything but authorized → Welcome
   - No local profile → Welcome
4. After sign-in (and on every launch), scrapbooks and photos from the user's ended rolls are restored in the background, e.g. on a new phone (change 012). No restore UI
5. Sign out (in Profile Settings via "Log Out" and confirmation, change 088): returns to onboarding slides before Welcome (change 074); local data is kept
Edge cases:
- Cancel: stay on Welcome, no message
- Sign-in fails (including no Apple Account on the device): stay on Welcome with an error message
- No network: cannot sign in (Welcome shows an offline message and the sign-in button is disabled). Already signed in users can still enter (see step 3)
- Needs internet: Create Roll, Join Roll (QR, roll code, share link), invite / share link. Works offline: Home, Profile, viewing scrapbooks and photos, editing captions, Sign Out. How online-only features look and behave while offline: [Open]
- First launch: Onboarding slides before Welcome (change 074)
- Apple ID revoked while the app is running: caught on the next launch (no live sign-out)

## F2: Join a Roll [Locked]
1. Friend joins by entering the 6-character roll code (Workbench → camera → "Join a Roll"), or by opening the host's iCloud invite link (from AirDrop or a messaging app), which opens ScrapIt and joins directly. No QR code
2. Friend lands in the lobby as a participant; late joining is allowed while the roll lasts (goes straight to the camera if the roll is live)
3. Codes and links stay valid until the roll ends or the host deletes it
4. Same iCloud as the host (same or another device): opening the link or entering the code goes straight into the room as the host; no error, no extra participant. Joining again never adds the same person twice
5. Join Roll screen (change 019): "Turn on AirDrop to accept the invite" hint, then the code. The code field accepts letters / numbers only (uppercased, max 6); backspace, editing and paste work
6. While joining (code or invite link), a full-screen Joining overlay shows a film canister pulling its film strip out and in, with status text by wait time; Cancel closes it (a late failure is ignored, a late success leaves the room again; nothing to leave when opened as the host) (change 024)
Edge cases:
- Fewer than 6 characters: "Enter all 6 characters of the code", no server call (change 019)
- Code not found, roll ended, offline, iCloud problem: the Joining overlay closes and Join Roll shows a short message only (an invite link shows the room message); technical detail goes to the developer log, never on screen (change 019)
- App not installed: the iCloud link shows Apple's iCloud web page pointing to the App Store

## F3: Roll (real-time shared capture session) [Locked]
1. Host taps the disposable camera on Workbench, taps "Create Roll"
2. Setup step: enters roll name, chooses shot count (24, 36, 48, 72; nothing picked at first) with friendship size guidance ("suitable for 2-3 / 4-6 / 7-8 / 8+ friends"); Next only once the name has text and a count is picked (change 081)
3. Filter step: chooses film filter ("Cinematic 400 Pro 35 Black & White" or "200 Color Print"); Done opens the lobby (change 081)
4. Lobby: roll title, stats (joined, shots) and participant avatars (initials). Host (change 019): "⋯" menu → Edit Room (only before the roll starts: Edit Roll name and shots → filter → Done saves and syncs to everyone; ‹ back without saving, change 081), Share Room (system share sheet), Delete Room (asks first with the Delete Roll card, then deletes it for everyone, change 081); a "+" tile after the avatars opens Invite Friends (Invite via AirDrop, or Invite via Room Code → the code, long-press copies it); long-press another person's avatar → Remove (no confirmation). Participant: "⋯" → Share Room, Leave Room (no confirmation [Open]). X (both) closes the lobby back to the Workbench; the roll keeps existing and can be reopened from the Workbench's film canisters → "Resume Roll" (change 106)
   - In **"Resume Roll"** (change 106), local non-ended rolls (`waiting` and `live`) list newest first and silently refresh from CloudKit on appear and tap: tapping `waiting` reopens its Lobby, tapping `live` opens its Lobby with "Continue Roll" (host and participants), which goes back into the Capture Session without the start step and its intro (change 081), and tapping a remotely ended roll finalizes it into Roll Reveal (or notifies if its scrapbook already exists locally). Roll status progresses monotonically (`waiting` → `live` → `ended`) so stale `"waiting"` snapshots never revert a started roll; if the host still has a local `.live` roll while CloudKit reports `"waiting"`, opening/refreshing the lobby or tapping "Continue Roll" re-publishes `.live` to CloudKit (change 148). Long-pressing a roll card offers **Leave Roll** (for hosts with other participants, transfers `hostUserID` to the next participant while preserving the CloudKit zone for others; when alone, deletes the room; participants leave the shared zone) and **Delete Roll** (host, with confirmation).
5. Host taps "Start Roll"; participants see "Waiting for the host to start..." and move to the camera when the host starts (only a roll that starts while they wait, change 081). If the host taps "Start Roll" before CloudKit room creation finishes, the local `.live` status is preserved and automatically published to CloudKit once room creation completes so waiting participants still move to the camera (change 148). Starting the roll, or a participant moving with it, triggers `CameraIntroTransitionOverlay` (change 110): cross-fades cleanly to a blank paper page (`#F4EFE6`), plays the 3D disposable camera film-loading sequence (fly-in, Y-axis flip, back door swing, filter-matched `FilterCanisterColor` / `FilterCanisterBW` insertion, leader pull, spool wind, door latch, thumb wheel advance, and deep viewfinder zoom with "Press anywhere to skip"), silently pushes `CaptureSessionView` underneath without a horizontal navigation slide, and fades into the live camera
6. Removed participants return to the Workbench with a short message; when the host deletes the roll, the host and everyone in it see the "Roll Deleted" card on the Workbench (change 081)
7. Everyone takes photos (still and Live Photo) at the same time in-app. Slot counts sync live in <50ms via Supabase Realtime broadcast (backed up by 3-second CloudKit polling, change 011). Photos are stored locally at optimized resolution (max 2048px still, 1440px movie, ~1.4 MB total per shot, change 014). Each shot uploads to iCloud in the background right after it is taken (once its shot is confirmed and its Live Photo movie is ready), also when the app is closed (change 020). Shutter tap immediately starts a rotating amber progress ring around the shots-left dial with a gentle sync pulse; the dial holds its count until CloudKit slot arbitration finishes, then decrements with an ultra-sharp mechanical click and normal odometer animation (change 058). Nobody, including the host, sees others' photos during the roll
   - During capture, tapping the leading Back button returns to Workbench/Homepage while keeping the roll session and host status active; re-entering via "Resume Roll" resumes capture. Exiting the camera view performs a multi-step return transition (changes 056, 086, 100, 110): closes the mechanical iris diaphragm over the live preview, zooms out from the optical viewfinder window of the disposable camera back (`DeskDisposableCameraBack`) to a centered floating card, performs a 3D horizontal flip around its local Y-axis to reveal the front disposable camera element (`DeskDisposableCamera`), silently pops to portrait WorkbenchView underneath, fades out the dark background, and spring-animates the camera element back to its idle position on the cutting mat, restoring the floating tab bar. Tapping the FLIP button triggers an 8-blade mechanical iris diaphragm closure over the preview while smoothly animating the zoom wheel to 1.0x with ratchet tick haptics (sliding hatch covers removed, change 072), reopening the iris after the wheel settles. Host can tap the dedicated End Roll button on the top-right camera deck to end the roll manually (changes 041, 072).
8. One shared pool of shots; any person's photo uses one shot
9. Roll ends when the shots run out OR the host ends it manually (change 099):
   - When the host taps the dedicated End Roll button, an "End this roll?" confirmation dialog (Figma 1517:25254) appears with dynamic shots remaining count ("1 shot left" / "N shots left") and Cancel / Yes actions.
   - When the host confirms Yes, or when all roll shots are captured, the "Roll Complete!" dialog (Figma 1512:26505) appears for all participants, displaying natural or early finish messaging.
   - Tapping "Reveal Photos" initiates a root-level full-screen fade through black, silently resetting orientation to portrait and opening the Roll Reveal envelope.
10. Photos are saved into a new shared scrapbook (others' photos become visible here). Everyone (host and participants) sees the Roll Reveal once (change 021): a closed envelope with the roll name and the number of photos on this phone ("Printing your photos…" while friends' photos arrive, the envelope bounces and the count rolls up; "Your photos are ready!" for 2.5 s when all are in, change 024; "Swipe or tap to open" once unlocked, change 075) → swipe across the translucent dashed tear-guide strip or tap the envelope to tear it open (change 075), once every photo is in or 10 s after the reveal opened (change 024) → the photos scatter on a cutting mat (drag to move; "Tidy Up" ↔ "Scatter" switches to a grid by time) → tap a photo for the detail (Save to Photos, a Live Photo as Live Photo; Share; tap outside closes) → "Start Scrapbook" opens the scrapbook editor (change 013). The reveal cannot be opened again
11. After End Roll the phone keeps fetching friends' photos every few seconds until it has all of the roll's shots, for up to 2 minutes; the reveal's count and photos update as they arrive, also after the tear (they land on the mat). Anything still missing comes with the next launch (change 020)
Edge cases:
- Network lost mid-roll: photos queue locally and upload when the app runs online again (launch or reconnect, change 020)
- Host disconnects: host role passes to the next participant
- Last-shot race: first write wins; the other photo is dropped and that user is told the roll finished

## F4: Profile bookshelf [Locked]
Figma nodes 1300:36434 (shelf), 1300:36485 (empty state), 1573:27257 / 1573:28563 / 1766:62644 (bookshelf reader); changes 088, 128.
1. User opens profile ("Library" tab) → sees wooden bookshelf (`1300:36434`) displaying rows of up to 12 vertical book spines per shelf plank. Spines react with tactile press lift and horizontal finger-drag proximity ripple across the shelf (`BookshelfRowView`, change 128). Tap a spine → presents `BookshelfReaderOverlay` directly over the softly blurred bookshelf (`5.5` pt blur, tab bar hidden): lifts and turns the tapped spine into the centered front cover (`BookPullOutView`), then hinges the front cover open in 3D (`BookCoverHingeView`, `-180°`) into the interactive two-page spread (`ScrapbookInteractiveSpreadBook`) with automatic Live Photo playback, 3D page turning, tap-to-zoom read-only page inspection (`ScrapbookEditorView`), and native Liquid Glass top bar controls (`✕` close back to shelf, title + `"Private"` subtitle, Collaborators `.popover`, and `"⋯"` menu with `"Delete Scrapbook"`). Long-press a spine → `.contextMenu` "Delete" → confirmation "Delete this scrapbook?" / "Its photos on this phone are deleted too." (local deletion, change 012).
2. Empty state (`1300:36485`): "Your bookshelf is waiting!", wooden shelf plank, and a "Create Roll" pill button routing directly to F3 Create Roll Setup (`AppRoute.createRollSetup`).

## F5: Scrapbook creation [Draft]
1. When a roll ends, a new scrapbook is created; after the Roll Reveal (F3 step 10, change 021) "Start Scrapbook" opens the scrapbook as a book on the desk with one spread (two empty pages, change 025); tapping the book zooms into the spread editor; the user adds the roll's photos (Live Photos included) from the Photos tray (change 022)
   - From the Home Workbench, tapping the red open toolbox opens **"Resume Editing"** (change 104), listing local scrapbooks not saved yet (change 125) newest first in a 2-column folder card grid (`FolderPreviewCard`). Tapping a folder opens its scrapbook editor; long-pressing removes only the local copy (`ScrapbookLocalDeletionService` + `DeletedScrapbookList`) without affecting collaborators. If no scrapbooks exist yet, **"Resume Editing"** shows an empty state whose `"Create Roll"` button starts F3 Create Roll Setup.
2. Friends' photos are added to the Photos tray as they arrive from the cloud (when the roll ends and on later launches)
3. Editor (ported from the camera POC; may change with the design): pages are always editable, tools in the leather tool tray (change 022): scissors, pencil (PencilKit drawing layers), stickers (Travel, Fun), photos, washi tape, cut-out letters, plain text. 3:4 pages shown two at a time (spreads, change 025): swipe the book to turn a page like a real book; past the last spread "+ Add page" adds two empty pages (change 121); in the edit view X goes back to the book, zoom cycles both pages → left → right, items can cross the gutter on the spread, Who's here lists people per page, undo / redo covers every change; only the two-page spread turns to landscape. Items moved / resized / rotated (pinch or the corner handle; a tapped pencil drawing too, change 150), double tap a photo for full screen, Live Photos loop on the page without stopping other apps' music (change 023). No markup (PaperKit needs iOS 26)
4. Finishing (change 026): the first time a scrapbook's book opens for editing, a welcome card shows once (change 125). ✓ at the top right of the book view asks "Done editing your pages?" (Cancel / Edit Cover → Edit Cover, its ✓ → the cover screen); nothing is finished yet: ‹ on the cover screen goes back to the pages, and a scrapbook left on the cover screen opens there again (change 125). Edit Cover decorates the front (Pencil, Stickers, Washi, Letters, Text) and the spine (Pencil, Stickers, Text), cover color with the texture kept; titles are typed with Text. A participant taps Done Editing ("Nice Work!", then read-only, Back to Home); the host taps Save Scrapbook (asks first only while someone else is In Progress) → locked for everyone → "Scrapbook Complete!" → View Bookshelf (Profile tab). Editing Progress lists Done Editing / In Progress members; the host is Done while on the cover screen and In Progress on the pages or in Edit Cover, synced both ways (`editing_resumed`, the room's done record removed), Done for good after Save (change 125). Reading a saved or done scrapbook: tap the book → the two-page view read only (no tools), X back, zoom button and two-finger zoom (change 125)
5. A finished or locked scrapbook opened via `ScrapbookCoverScreen` starts on the closed book; tapping it hinges the front cover open in 3D (`BookCoverHingeView`, change 128) into the read-only two-page spread (and folds back closed on `✕`). From the Profile bookshelf, tapping a spine opens `BookshelfReaderOverlay` directly over the blurred shelf (change 128).
6. Only ended rolls create scrapbooks; no empty scrapbook, no renaming
Layouts (pages, positions, cuts, drawings) are stored on this device: not restored on a new phone. Friends who have the same scrapbook open see all toolbar changes live (change 042, 062): photos (single-use per roll across pages until removed), Travel and Fun stickers (including shared single-use sheet slots, slot restoration on removal, and "Take a New Sheet"), letters, text (add/edit/clear), washi, Pencil drawing layers (Last-Write-Wins), Live Photo motion toggles, cuts and cut undo, item transforms/removals, backgrounds, and page add/move/delete; changes made while a friend is away don't reach them later. Undo / redo is sent with the same events (last write wins, change 025). The cover (front and spine items, color), Done Editing and the lock are shared live too (change 026); Done Editing and the lock are also kept in the CloudKit room.
